# Security Policy

Security issues should be handled privately and responsibly.

## Reporting a vulnerability

**Do not open a public issue for a suspected security vulnerability.**

For repositories with GitHub Private Vulnerability Reporting enabled, use the repository's **Security → Advisories → Report a vulnerability** flow.

If private vulnerability reporting is not available, contact the repository maintainers privately through an established Drakeshard contact channel. A dedicated security email will be published here when one is available.

Please include, where possible:

- A clear description of the issue
- Affected repository, version, branch, or commit
- Steps to reproduce
- Potential impact
- Proof-of-concept details that are safe to share privately
- Any suggested remediation

## Sensitive information

Do not include production credentials, private keys, personal data, access tokens, or other unrelated sensitive information in a report.

## Response process

We aim to:

1. Confirm receipt of a valid report.
2. Reproduce and assess the issue.
3. Develop and test a fix.
4. Coordinate disclosure where appropriate.
5. Publish remediation information after affected users can reasonably update.

Response timing depends on severity, reproducibility, and maintainer availability.

## Supported versions

Support policy is repository-specific. Check the target repository's documentation and releases for currently maintained versions.

## Scope

This policy applies to software maintained by Drakeshard Studios. Vulnerabilities in third-party services or dependencies should also be reported to the relevant upstream maintainers when appropriate.
